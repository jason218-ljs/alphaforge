# AlphaForge 开发规范

> **目的**：保证多人协作下代码质量一致、可被 Trae 工作流稳定驱动、测试可追溯
> **适用**：AlphaForge 项目全部源码、测试、脚本、文档、工作流

---

## 一、目录纪律（对齐根目录 `文件夹规范.md`）

### 1.1 项目根目录

```
AlphaForge/
├── src/alphaforge/        # 源代码（唯一）
├── tests/                 # 测试（唯一）
├── docs/                  # 文档（唯一）
├── scripts/               # 项目专属脚本
├── data/                  # 原始输入数据（gitignore）
├── output/                # 输出报告（gitignore）
├── pyproject.toml
├── config.yaml
└── .gitignore
```

**禁止**：
- 项目根目录直接放 `.py` / `.xlsx` / `.txt` / `.json` / `.csv` 文件
- 项目根目录直接放 `.md` 文档（必须进 `docs/`）
- 在 `src/` 之外写业务代码

### 1.2 src/alphaforge 内部分层

```
src/alphaforge/
├── models/        # 纯数据模型，零业务逻辑，零外部依赖
├── data/          # 数据接入，依赖 models
├── engine/        # 回测引擎，依赖 models
├── strategy/      # 策略，依赖 models + engine
├── analysis/      # 分析，依赖 models
├── reporting/     # 报告，依赖 models + analysis
├── integration/   # 外部桥接（可选依赖，必须 try/except 降级）
├── utils/         # 工具函数，无状态
├── cli.py         # CLI 入口
├── config.py      # 配置加载
├── logger.py      # 日志
└── orchestrator.py # 工作流编排
```

**依赖方向**（严禁反向）：
```
cli/orchestrator → reporting → analysis → engine → data → models → utils
                                                       ↑
                                                  strategy
```
- `models` 不依赖任何上层
- `utils` 不依赖任何上层
- `integration` 可横向依赖外部项目，但必须 try/except，不阻断主流程

### 1.3 tests 镜构

```
tests/
├── unit/           # 单元测试，镜像 src 结构
│   ├── models/
│   ├── data/
│   ├── engine/
│   ├── analysis/
│   └── reporting/
├── integration/    # 集成测试（跨模块）
├── e2e/            # 端到端测试（CLI 命令级）
├── fixtures/       # 测试数据（小 Excel 样本等）
└── conftest.py     # pytest 公共夹具
```

## 二、命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 包/模块 | snake_case | `alphaforge.engine.event_engine` |
| 类 | PascalCase | `BacktestEngine`, `主流水线Importer` |
| 函数/方法 | snake_case | `on_bar`, `import_file`, `calculate_sharpe` |
| 变量 | snake_case | `daily_returns`, `max_drawdown` |
| 常量 | UPPER_SNAKE | `STAMP_TAX_RATE`, `DEFAULT_BENCHMARK` |
| 私有 | 前缀 `_` | `_parse_sheet_name`, `_check_t_plus_1` |
| 文件 | snake_case | `external_scorer_importer.py`, `market_rules.py` |
| 测试文件 | `test_<被测模块>.py` | `test_backtest_engine.py` |
| 配置键 | snake_case | `risk_free_rate`, `enable_t_plus_1` |
| CLI 子命令 | 动词 | `replay`, `backtest`, `optimize`, `analyze` |

**股票代码规范**：统一 6 位 + 后缀，如 `600519.SH`、`000001.SZ`、`300750.SZ`、`688981.SH`。板块识别用代码前缀。

## 三、代码规范

### 3.1 类型注解（强制）

所有 public 函数必须 100% 类型注解：

```python
# 正确
def calculate_sharpe(returns: pd.Series, risk_free_rate: float = 0.03) -> float:
    ...

# 错误
def calculate_sharpe(returns, risk_free_rate=0.03):
    ...
```

### 3.2 Docstring（强制）

所有 public 函数/类用 Google 风格 docstring：

```python
def import_file(self, path: Path) -> Dict[datetime, DailyRecord]:
    """导入 主流水线 多 sheet Excel，返回按日期索引的日度记录。

    Args:
        path: Excel 文件路径。

    Returns:
        Dict[datetime, DailyRecord]：键为交易日期，值为当日记录（含流水、组员、NAV）。

    Raises:
        FileNotFoundError: 文件不存在。
        ValueError: Sheet 名无法解析为日期。
    """
```

### 3.3 数据模型（pydantic v2）

```python
from pydantic import BaseModel, Field, field_validator

class Bar(BaseModel):
    date: datetime
    code: str
    open: float = Field(ge=0)
    high: float = Field(ge=0)
    low: float = Field(ge=0)
    close: float = Field(ge=0)
    volume: int = Field(ge=0)
    amount: float = Field(ge=0, default=0.0)

    @field_validator("high")
    @classmethod
    def high_ge_low(cls, v, info):
        if "low" in info.data and v < info.data["low"]:
            raise ValueError("high must >= low")
        return v
```

### 3.4 异常处理

- **边界层**（文件 I/O、HTTP API、Excel 解析）：必须 try/except，降级为默认值或日志告警
- **业务层**（engine/analysis）：抛出语义化异常，不静默吞掉
- **禁止**裸 `except:`，必须 `except SpecificError:`
- **禁止**用异常做控制流

```python
# 正确
try:
    quote = self.api.fetch(code)
except (ConnectionError, TimeoutError) as e:
    logger.warning(f"行情获取失败 {code}: {e}，使用缓存")
    quote = self.cache.get(code)

# 错误
try:
    ...
except:
    pass
```

### 3.5 日志

```python
import logging
logger = logging.getLogger(__name__)

logger.debug("开始导入 %s", path)
logger.info("导入完成：%d 个交易日", len(records))
logger.warning("Sheet %s 解析失败，跳过", sheet_name)
logger.error("撮合失败：%s", order, exc_info=True)
```

- 日志用 `%` 占位符（延迟格式化），不用 f-string（性能）
- 模块级 `logger = logging.getLogger(__name__)`，不实例化全局 logger

### 3.6 配置注入

- 严禁在业务模块 `from config import CONFIG`（硬耦合）
- 配置通过构造函数注入：

```python
class RiskAnalyzer:
    def __init__(self, config: AnalysisConfig):
        self.risk_free_rate = config.risk_free_rate
        self.annualization = config.annualization_factor
```

## 四、测试规范

### 4.1 测试分层与覆盖目标

| 层 | 目录 | 覆盖目标 | 占比 |
|----|------|---------|------|
| 单元测试 | `tests/unit/` | 函数/类级别，隔离依赖 | 70% |
| 集成测试 | `tests/integration/` | 跨模块协作 | 20% |
| 端到端 | `tests/e2e/` | CLI 命令完整链路 | 10% |

**整体覆盖率 ≥80%**，核心模块（engine/analysis/data importer）**≥90%**。

### 4.2 单元测试规范

```python
# tests/unit/analysis/test_risk_analyzer.py
import pytest
import pandas as pd
from alphaforge.analysis.risk_analyzer import RiskAnalyzer
from alphaforge.config import AnalysisConfig

@pytest.fixture
def analyzer():
    config = AnalysisConfig(risk_free_rate=0.03, annualization_factor=252)
    return RiskAnalyzer(config)

@pytest.fixture
def returns():
    return pd.Series([0.01, -0.02, 0.03, 0.005, -0.01])

class TestSharpeRatio:
    def test_positive_sharpe(self, analyzer, returns):
        sharpe = analyzer.calculate_sharpe(returns)
        assert sharpe > 0

    def test_zero_volatility_returns_zero(self, analyzer):
        sharpe = analyzer.calculate_sharpe(pd.Series([0, 0, 0]))
        assert sharpe == 0

    def test_includes_risk_free_rate(self, analyzer, returns):
        sharpe = analyzer.calculate_sharpe(returns, risk_free_rate=0.03)
        # 减无风险利率后应低于不减的
        sharpe_no_rf = analyzer.calculate_sharpe(returns, risk_free_rate=0)
        assert sharpe < sharpe_no_rf
```

### 4.3 测试命名

- 文件：`test_<被测模块>.py`
- 类：`Test<被测类>`
- 方法：`test_<场景>_<预期>`
- 用 `describe` 风格命名，如 `test_max_drawdown_with_single_peak_returns_correct_value`

### 4.4 测试数据

- 小数据集放 `tests/fixtures/`（如 5 行的 mini Excel）
- 禁止依赖网络（行情 API 用 mock）
- 禁止依赖外部路径（用 `tmp_path` fixture）

```python
def test_importer(tmp_path):
    excel = tmp_path / "mini.xlsx"
    # 构造最小 Excel ...
    importer = 主流水线Importer()
    records = importer.import_file(excel)
    assert len(records) == 5
```

### 4.5 测试运行

```bash
# 全量
pytest tests/ --cov=alphaforge --cov-report=html

# 仅单元
pytest tests/unit/ -v

# 按模块
pytest tests/unit/analysis/ -k "sharpe"

# 失败时打印局部变量
pytest tests/ -l --tb=short
```

**提交前必须**：`pytest tests/ --cov=alphaforge --cov-fail-under=80` 通过。

## 五、工作流规范（Trae 驱动）

### 5.1 workflow md 文件层级

```
docs/workflow/
├── main-auto-workflow.md          # 主编排（调度子 flow）
├── data-auto-flow.md              # 数据导入子 flow
├── backtest-auto-flow.md          # 回测执行子 flow
├── analysis-auto-flow.md          # 分析评估子 flow
└── report-auto-flow.md            # 报告生成子 flow
```

### 5.2 workflow md 标准范式

每个 workflow md 必须包含以下章节（对齐 `学习资料/投资知识图谱/07_核心工作流程.md` 范式）：

```markdown
# <Flow 名称> auto-flow

> 目标：一句话说明本 flow 解决什么问题

## 流程图
（ASCII 框图，展示步骤与分支）

## 前置条件
- 输入文件 / 配置项 / 环境依赖

## 步骤详解

### Step 1: <动作>
- 目的：
- 输入：
- 输出：
- 调用：
  ```bash
  python -m alphaforge.cli <subcommand> ...
  ```
- 校验：（如何确认成功）

### Step 2: ...

## 数据模型
（本 flow 产生/消费的核心数据结构）

## 配置项
（本 flow 读取的 config.yaml 段）

## 失败容忍
（异常情况下的降级策略）

## 验证方案
（单元/集成测试如何覆盖本 flow）
```

### 5.3 Trae 调用约定

- Trae 按 `main-auto-workflow.md` 的 Step 顺序执行
- 每个 Step 调用一个 `python -m alphaforge.cli <subcommand>` 或 Python API
- Step 之间通过 `output/` 目录的 JSON 文件传递中间结果（解耦）
- 每个 Step 必须有"校验"小节，Trae 据此判断是否进入下一步

### 5.4 Orchestrator 接口

`src/alphaforge/orchestrator.py` 暴露与 workflow Step 一一对应的方法：

```python
class Orchestrator:
    def run_data_import(self, excel_path: str) -> str: ...      # 返回输出 JSON 路径
    def run_backtest(self, strategy: str, params: dict) -> str: ...
    def run_analysis(self, backtest_result_path: str) -> str: ...
    def run_report(self, analysis_result_path: str) -> str: ...
    def run_full_cycle(self, excel_path: str) -> dict: ...      # main-auto-workflow 全链路
```

CLI 子命令直接转发到 Orchestrator，保证 CLI / Python API / Workflow 三者一致。

## 六、配置规范

### 6.1 config.yaml 为单一真源

- 所有可调参数集中在 `config.yaml`
- 代码内 `config.py` 只放默认值（config.yaml 缺失时兜底）
- **禁止**业务模块硬编码阈值

### 6.2 配置分层

```python
# config.py
@dataclass
class MarketRulesConfig:
    stamp_tax_rate: float = 0.001
    commission_rate: float = 0.00025
    ...

@dataclass
class AnalysisConfig:
    risk_free_rate: float = 0.03
    ...

@dataclass
class AlphaForgeConfig:
    market_rules: MarketRulesConfig
    analysis: AnalysisConfig
    ...

    @classmethod
    def from_yaml(cls, path: Path) -> "AlphaForgeConfig": ...
```

### 6.3 配置覆盖优先级

```
默认值 < config.yaml < 环境变量 ALPHAFORGE_* < CLI 参数
```

|------|----|------|

## 十、文档规范

- `docs/` 下所有 `.md` 用中文，代码块用英文注释
- 架构变更必须同步更新 `系统设计方案.md`
- 新增 CLI 子命令必须更新 `main-auto-workflow.md`
- 新增模块必须在 `系统设计方案.md` 的模块划分中登记
- `README.md` 只放快速上手，详细设计进 `docs/`
