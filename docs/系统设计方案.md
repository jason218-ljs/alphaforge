# AlphaForge 系统设计方案

> **版本**：v1.0
> **定位**：企业级量化分析回测引擎
> **数据源**：投资流水记录表（多 sheet Excel，每日 1 sheet）
> **基础**：融合 `PortfolioAnalyzer`（分析层）与 `Buffett-Value-Agent`（回测引擎 v2）的成熟资产，补齐归因 / 寻优 / 稳健性 / 工作流编排能力

---

## 一、项目定位与目标

### 1.1 痛点诊断

| 既有项目 | 能力 | 缺口 |
|---------|------|------|
| PortfolioAnalyzer | 日度快照分析、风险/收益/策略指标、Excel 导入、报告生成 | **无真正回测引擎**（只累加流水做统计）、夏普未减无风险利率、Calmar/Alpha 公式有 bug、无归因、无寻优、无稳健性检验 |
| Buffett-Value-Agent | 事件驱动回测 v2（T+1/涨跌停/费用/滑点）、80 维因子、PIT 库、多源容灾 | v1/v2 割裂、config 与引擎常量未打通、组合相关性留空、测试覆盖 ~20%、agent.py 单文件 4500 行 |

### 1.2 AlphaForge 的目标

构建一个**单一职责清晰、可独立运行、可被 Trae 工作流驱动**的企业级分析回测系统：

1. **真回测**：事件驱动 + 向量化双路径，支持 T+1 / 涨跌停 / 费用 / 滑点
2. **真分析**：修正全部已知指标 bug，补齐 Brinson 归因、Fama 五因子
3. **真寻优**：网格 + 贝叶斯（Optuna）参数寻优，Walk-Forward + Monte Carlo 稳健性检验
4. **真数据**：PIT 数据库杜绝未来函数，多源容灾 + 多级缓存
5. **真工程**：src 布局、pydantic 模型、pytest 测试覆盖 ≥80%、YAML 配置驱动
6. **真工作流**：Trae 驱动的 `main-auto-workflow.md` + 子 `auto-flow.md`，按文件调用 Python

### 1.3 与既有项目的关系

```
ExternalScorer ──┐
                    ├──(评分/选股)──► AlphaForge ──(回测/归因)──► AlphaMonitor(监控)
Buffett-Value-Agent ┤                       │
                    │                       ├──(组合分析)──► PortfolioAnalyzer
PortfolioAnalyzer ──┘                       │
                                            └──(报告)──► 飞书/钉钉/邮件
```

AlphaForge **不重复造轮子**：
- 评分 / 选股 → 复用 ExternalScorer / Buffett-Value-Agent（通过 integration 桥接，可选）
- 监控 → 复用 AlphaMonitor
- AlphaForge 聚焦 **回测 + 分析 + 归因 + 寻优 + 报告** 这一垂直链路

## 四、回测引擎设计（核心）

### 4.1 双路径设计

| 路径 | 文件 | 范式 | 速度 | 灵活度 | 用途 |
|------|------|------|------|--------|------|
| 事件驱动 | `event_engine.py` | 逐 bar 回调 Strategy.on_bar | 慢（1x） | 高（支持任意逻辑） | 复杂策略、多标的、动态仓位 |
| 向量化 | `vectorized_engine.py` | pandas 矩阵运算 | 快（100x） | 低（信号预计算） | 参数寻优、大规模筛选 |

两路径共享 `Matcher`、`Portfolio`、`MarketRules`、`BacktestResult`，保证结果一致性。

### 4.2 A 股市场规则（`market_rules.py`）

复用 BVA v2 的成熟常量，统一为配置驱动：

```python
# 所有常量从 config.yaml 读取，此处为默认值
STAMP_TAX_RATE = 0.001        # 印花税 0.1%（卖出征收）
COMMISSION_RATE = 0.00025     # 佣金 0.025%
MIN_COMMISSION = 5.0          # 最低佣金 5 元
TRANSFER_FEE_RATE = 0.00002   # 过户费 0.002%
SLIPPAGE_PCT = 0.0005         # 滑点 0.05%
SLIPPAGE_FIXED = 0.01         # 固定滑点 0.01 元

# 涨跌停（按板块）
PRICE_LIMIT = {
    "MAIN": 0.10,   # 主板 ±10%
    "GEM":  0.20,   # 创业板 ±20%
    "STAR": 0.20,   # 科创板 ±20%
    "BEI":  0.30,   # 北交所 ±30%
}

# T+1
ENABLE_T_PLUS_1 = True         # 当日买入次日可卖
```

板块识别规则：`60xxxx→MAIN`、`30xxxx→GEM`、`68xxxx→STAR`、`8xxxxx/4xxxxx→BEI`、`00xxxx→MAIN`。

### 4.3 撮合流程（`matcher.py`）

```
Order 进入
   │
   ├─► 校验：代码合法？数量 100 整数倍？价格 > 0？
   │
   ├─► T+1 检查：若为卖出，查 today_buy_lots[code]，拒绝卖出当日买入股
   │
   ├─► 涨跌停检查：prev_close × (1±limit) 上下界，超界拒绝
   │
   ├─► 滑点：买价 = price × (1+slippage_pct) + slippage_fixed
   │         卖价 = price × (1-slippage_pct) - slippage_fixed
   │
   ├─► 费用：佣金 = max(amount × commission_rate, min_commission)
   │         印花税 = amount × stamp_tax_rate（卖出）
   │         过户费 = amount × transfer_fee_rate
   │
   ├─► 资金检查：买入需 cash ≥ amount + fee；卖出需持仓 ≥ qty
   │
   └─► 生成 Fill，更新 Portfolio（cash / position / realized_pnl）
```

### 4.4 组合状态机（`portfolio.py`）

```python
@dataclass
class Portfolio:
    cash: float
    positions: Dict[str, Position]          # code → Position
    history: List[PortfolioSnapshot]         # 每日快照
    today_buy_lots: Dict[str, int]           # T+1 跟踪，每日清零

    def apply_fill(self, fill: Fill): ...
    def mark_to_market(self, date, quotes: Dict[str, Bar]): ...
    @property
    def nav(self) -> float: return self.cash + sum(p.market_value for p in ...)
```

### 4.5 策略基类（`strategy/base.py`）

```python
class StrategyBase(ABC):
    @abstractmethod
    def initialize(self, ctx: Context) -> None: ...
    @abstractmethod
    def on_bar(self, ctx: Context, bar: Bar) -> List[Order]: ...
    def on_fill(self, ctx: Context, fill: Fill) -> None: ...
    def on_day_end(self, ctx: Context, date: datetime) -> None: ...
```

`Context` 注入 `portfolio / history / calendar / config / logger`，策略只读不写状态。

## 五、分析指标体系（修正版）

### 5.1 修复清单（对齐 PortfolioAnalyzer 的 bug）

| 指标 | 旧实现 bug | AlphaForge 修正 |
|------|-----------|----------------|
| 夏普比率 | 未减无风险利率 | `sharpe = (mean(rf) - rf) / std * sqrt(252)`，rf 来自 config |
| Calmar | `hasattr(result, 'annualized_return')` 永远 False | 直接用 `annualized_return / abs(max_drawdown)` |
| Alpha | benchmark 用硬编码 8% | 用真实基准序列回归：`alpha = mean(Rp - β·Rb)` |
| Beta | benchmark 未填充 | `beta = cov(Rp,Rb)/var(Rb)`，真实基准 |
| avg_holding_period | 死代码（列表永远空） | 从 trade_log 计算开仓-平仓间隔 |
| benchmark_return | 主流水线Importer 不解析 | 独立 BenchmarkManager 加载沪深300 |

### 5.2 指标全景

**风险指标**（`risk_analyzer.py`）：
- 最大回撤 MDD / 峰值净值 / 回撤持续期 / 恢复期
- 年化波动率 `std(daily_ret) × sqrt(252)`
- 下行波动率（仅负收益）
- VaR 95% / CVaR 95%（历史模拟法）
- 夏普 / Sortino / Calmar / 信息比率 IR

**收益指标**（`return_analyzer.py`）：
- 累计收益 / 年化收益 / 日均收益
- 胜率 / 盈亏比 / 平均盈亏
- Alpha / Beta（CAPM 回归）
- 超额收益 / 跟踪误差

**策略指标**（`strategy_evaluator.py`）：
- 信号胜率 / 信号盈亏比
- 平均持仓周期
- 执行率（信号→成交）
- 策略漂移检测（近 20 日 vs 全期）
- 市场适应性（涨/跌市分桶）

**归因指标**（`attribution.py`，新增）：
- **Brinson 行业归因**：配置效应 + 选股效应 + 交互效应
- **Fama 分解**：系统性收益 + 选股回报 + 风险回报

## 六、参数寻优与稳健性

### 6.1 参数寻优（`optimizer.py`）

- **网格搜索**：`itertools.product` 笛卡尔积，目标函数 = 夏普（约束 MDD<20%）
- **贝叶斯优化**：Optuna TPE 采样器，支持早停、剪枝
- **目标函数可配置**：sharpe / sortino / calmar / total_return / custom

### 6.2 稳健性检验（`robustness.py`）

- **Walk-Forward Analysis**：滚动窗口 train→test，检查参数稳定性
- **Monte Carlo**：对 trade_log 做重采样（有放回），生成绩效分布
- **参数敏感性**：邻域扰动，输出指标变化率

## 七、主流水线 Excel 导入设计

### 7.1 Excel 结构（实测）

```

R2:  说明（资金约束）

R6:  一、小组当日汇总（表头 R7）
R8:  汇总数据（格式化字符串：'5,000,000', '0.29%'）
R9:  汇总数据（原始数值：5000000, 0.0029）← 优先用此行
R11: 二、组员个人资产快照（表头 R12）
R13: 示例行（跳过，以"示例"开头）
R14-R18: 5 名组员真实数据
```

### 7.2 导入器设计

```python
class 主流水线Importer:
    def import_file(self, path: Path) -> Dict[datetime, DailyRecord]: ...
    def import_history(self, dir: Path) -> List[DailyRecord]: ...

    # 增量构建持仓（核心）
    def build_portfolio_history(self, records: List[DailyRecord]) -> List[PortfolioSnapshot]:
        """
        按日期排序，遍历每个 sheet 的 trades，累加仓位：
        - 买入：qty += trade.qty; avg_cost = (old_cost + amount) / new_qty
        - 卖出：realized_pnl += (price - avg_cost) * qty; qty -= trade.qty
        每日结束 mark-to-market（用成交价或行情接口），生成 PortfolioSnapshot
        """
```

**与 PortfolioAnalyzer 的差异**：
- 用 R9 原始数值行（而非 R8 格式化字符串），避免解析逗号/百分号
- 过滤"示例"行（R13、R22-23），而非依赖三元组去重
- 不按行号硬编码，用表头扫描定位（R7/R12/R21），模板变动更健壮
- 生成 `PortfolioSnapshot`（含持仓明细 + NAV），而非仅 `DailyRecord`

## 十、可视化 UI 设计（直观美观展示）

### 10.1 定位

报告层产出的是**数据态**（txt + json），viz 层负责**呈现态**：用 Web 仪表盘让报告结果直观可读。viz 是 reporting 的下游消费者，不重复计算，只读取 `output/` 下的 JSON 渲染。

### 10.2 技术选型

| 层 | 技术 | 理由 |
|----|------|------|
| 后端 | Flask（轻量，单文件 API） | 无需异步，部署简单 |
| 前端 | HTML + ECharts + Tailwind CSS | ECharts 金融图表成熟，Tailwind 快速美观 |
| 模板 | Jinja2 | Flask 原生支持 |
| 依赖 | flask（可选） | 缺失时 `alphaforge viz` 子命令降级提示 |

### 10.3 页面结构

**仪表盘主页 `dashboard.html`**：
- 顶部 KPI 卡片：总收益 / 年化 / 最大回撤 / 夏普 / 胜率（带颜色与图标）
- 权益曲线图（ECharts line，叠加基准沪深300）
- 回撤水下图（underwater plot，红色填充）
- 持仓饼图（按市值）+ 行业分布柱图
- 风险预警卡片列表（按优先级）

**回测详情页 `backtest.html`**：
- 逐笔交易表（可排序/筛选）
- 月度收益热力图（年×月）
- 个股贡献排名（正/负贡献柱图）
- 参数敏感性曲线（若跑了寻优）

**归因详情页 `attribution.html`**：
- Brinson 归因瀑布图（配置效应→选股效应→交互效应→总超额）
- Fama 分解饼图（系统性/选股/风险回报占比）
- 行业归因矩阵热力图

### 10.4 API 端点（`api.py`）

| 端点 | 返回 |
|------|------|
| `GET /api/dashboard?date=YYYYMMDD` | KPI + 权益曲线 + 持仓 + 预警聚合 |
| `GET /api/backtest?name=xxx` | 回测明细 + 月度热力 + 个股贡献 |
| `GET /api/attribution?date=xxx` | Brinson + Fama + 行业矩阵 |
| `GET /api/equity_curve?date=xxx` | 权益 + 基准序列 |
| `GET /api/positions?date=xxx` | 持仓明细 + 建议 |

### 10.5 启动方式

```bash
alphaforge viz --port 8050          # 启动仪表盘
alphaforge viz --report output/20260731-详细数据.json  # 指定报告
```

viz 层只读 `output/` 目录，无需数据库，可离线运行。
